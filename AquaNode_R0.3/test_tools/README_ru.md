# Исходные журналы

Требуются Python 3.10+ и `pyserial==3.5`. Эти программы работают на ноутбуке и не являются прошивкой узлов.

Установить зависимость: `python -m pip install pyserial==3.5`.

В двух терминалах для реально подключённых COM-портов:

```text
python log_capture.py --port COM5 --role tx --run-id water-001 --out tx.jsonl
python log_capture.py --port COM6 --role rx --run-id water-001 --out rx.jsonl
```

Остановить Ctrl+C. Файлы не перезаписываются. Указать существующую папку вывода. Открытие COM-порта может перезапустить XIAO: начинать испытание после открытия обоих журналов. При потере соединения не считать журнал полным; повторить прогон с новым run_id. Последний незавершённый фрагмент сохраняется с пометкой.

Прошивка должна выводить по одному JSON-объекту на строку. Обязательные поля: `event` (`TX_DONE` на передатчике после успешного завершения передачи, `RX_OK` после проверки CRC на приёмнике), `node_id` (строка), `boot_id` (уникальная строка после каждого перезапуска), `seq` (неотрицательное целое, новое значение для нового измерения). При повторной передаче одного измерения его три идентификатора не менять. В RX сохраняются идентификаторы исходного датчика, а не ретранслятора.

Дополнительные поля: `uptime_ms`, `temp_c`, `adc_ph_raw`, `adc_bat_raw`, `ph`, `battery_v`, `calibration_id`, `sensor_status`, `rssi_dbm`, `snr_db`, `frequency_hz`, `route`, `hop_count`, `firmware_version`. Неисправный датчик передавать как `null` со статусом ошибки, не как нулевое измерение. Время UTC в оболочке — время получения строки ноутбуком, не гарантированное время измерения. Для задержки доставки нужны синхронизированные часы или отдельная методика.

Каждая строка сохраняет исходные байты в base64, время UTC и монотонные часы ноутбука. Ошибки формата остаются в журнале. Это позволяет проверить исходные сообщения; формат сам по себе не обеспечивает криптографическую достоверность.

```text
python delivery_report.py --tx tx.jsonl --rx rx.jsonl --run-id water-001 > delivery.json
```

Отчёт считает уникальные измерения и совпадения по `(node_id, boot_id, seq)`, отдельно показывает повторы и пакеты вне TX-журнала. Это доставка измерений после возможных повторов, а не вероятность успеха одной радиопопытки. Для последней добавить attempt_id и анализировать попытки отдельно. Без реального TX-журнала нельзя восстановить знаменатель по максимальному seq: перезапуски и потери начала/конца исказят результат. При пустом TX выводится null, а не 100%.

Проверки этих программ проводились только на синтетических сообщениях. Реальных измерений в пакете нет.
