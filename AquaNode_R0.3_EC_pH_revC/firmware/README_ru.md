# Прошивка ec_ph_bench revC

Цель: XIAO ESP32S3, Arduino ESP32; включить USB CDC on boot. Внешние библиотеки: OneWire и DallasTemperature. ADS1115 читается штатной Wire, дополнительная ADS-библиотека не требуется.

- GPIO1 — EC_ADC; GPIO2 HIGH включает прежний boost/LDO для SEN0244.
- GPIO43 — DS18B20; `Serial` только USB CDC, не UART0 TX.
- GPIO5/GPIO6 — I²C SDA/SCL 100 кГц; ADS1115 0x48, AIN0/GND, ±4,096 В, 16 SPS, single-shot. Конфигурационное слово 0xC323. Есть проверка I²C, конфигурации, готовности и тайм-аут 150 мс.
- GPIO4 BAT_EN остаётся LOW; батарея не измеряется, радио не инициализируется.

pH активен: после начальной стендовой паузы 60 с прошивка считывает `ph_adc_mv` в каждом цикле вместе с температурой и EC. Внешний источник развязки включает оператор последним; прошивка им не управляет и не измеряет его напряжение. 60 с — начальная пауза, а не доказанное время стабилизации; перед калибровкой дождаться фактической устойчивости.

`ph_adc_mv` — напряжение AIN0 **после** делителя. Оно не равно напряжению электрода или AFE. При ошибке I²C/ADC выдаётся `null`. Выключенный или отсоединённый электрод не всегда можно распознать по допустимому напряжению — автоматического контроля состояния электрода нет.

Численное `ph` по умолчанию `null`, поскольку отсутствуют реальные калибровочные коэффициенты. Оно появляется после реальной калибровки, допуска питания и совместной работы, только в измеренном диапазоне и при температуре калибровки ±0,5 °C. Это не выключает физическое питание или чтение pH. `PH_SUPPLY_VALIDATED` и `PH_COEXISTENCE_VALIDATED` — ручные отметки, не автоматические датчики/защиты.

Калибровка:

```
python test_tools/export_ph_calibration.py measured_ph.json --out ph_calibration_new.h
```

Поля JSON описаны в `bench/Plan_ru.md`. Заменить `firmware/ec_ph_bench/ph_calibration.h` сгенерированным файлом, выставить допуски только по реальным отчётам, пересобрать прошивку. Сохранить хеш заголовка и бинарного файла с журналом. Начальные коэффициенты pH и EC — NAN; тестовые значения из тестов не загружать в прибор.

EC по-прежнему требует собственных реальных коэффициентов, допуска питания и температурной модели. В совместной revC выдача EC дополнительно требует `PH_COEXISTENCE_VALIDATED`. Без этого доступны исходные значения и статусы, но подтверждённых единиц измерения нет.

Схема USB JSONL: `aquanode.ecph.revC.v1`. Поля EC revB сохранены; добавлены `ph_adc_mv`, `ph`, `ph_status`, `ph_calibration_id`. `physical_validation=false` сохраняет статус стендового релиза; результаты аппаратных испытаний потребуют отдельного контролируемого выпуска. Радио, mesh, облако и deep sleep в этой версии отсутствуют.

Сборка: `repro/build_firmware.ps1`. Фактический результат сборки этой поставки смотреть в `checks/Verification_ru.md` и приложенном логе, не переносить статус из исторического revB.
